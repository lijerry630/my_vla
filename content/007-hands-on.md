## 先划清算力边界

| 阶段 | 显存 | 说明 |
| --- | --- | --- |
| SmolVLA 推理 | 8G 以内 | 异步推理，前台读图后台出动作 |
| π0 / π0.5 推理 | 8～16G | bf16 加载，动作分块后频率可用 |
| 7B 模型推理 | 16～24G | 需要 bf16，别用 fp32 |
| 小数据 LoRA 微调 | 24～48G | batch 压到 4～8，梯度累积补上 |
| 全参数微调 | 多卡 | 个人环境基本不用考虑 |

结论：4090（24G）可以完成「推理 + LoRA 微调」的完整闭环，这也是我给自己设的范围。

## 路线 A：LeRobot + SmolVLA

```bash
# 1. 环境（按你的 CUDA 版本选 tor>ch 组合，别混装）
conda create -n lerobot python=3.10 -y
conda activate lerobot
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
git clone https://github.com/huggingface/lerobot.git
cd lerobot && pip install -e .

# 2. 采集或下载一份小数据集，检查帧率与动作维度是否一致
python -m lerobot.scripts.visualize_dataset --repo-id <你的数据集>

# 3. 微调一个小模型：先冻结主干，只训动作头
python -m lerobot.scripts.train --policy.type smolvla ...

# 4. 部署，先离线回放同一批初始状态，再上真机
```

要点是**先验证数据管道，再验证模型**。数据管道里频率、维度、归一化任何一处不对，训练出来的 loss 都正常，但动作全偏。

## 路线 B：openpi 跑 LIBERO

openpi 把 π0 / π0.5 的训练与推理脚本一起放出来了，仿真环境能省掉真机调试的成本。顺序建议：

1. 先用官方给的 checkpoint 在 LIBERO 上跑通推理，确认环境、依赖、归一化统计都对
2. 再在同一套评测脚本下跑一次自己微调的模型，两次的脚本必须完全相同
3. 最后才换到自己的任务数据上

## 常见报错与排查顺序

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 动作幅度整体偏大/偏小 | 归一化统计量不匹配 | 用训练时的统计量推理 |
| 机械臂抖动 | 推理延迟 + chunk 过长 | 缩短 chunk，开滚动重规划 |
| loss 正常但成功率接近 0 | 相机外参或动作坐标系错 | 手眼标定复核 |
| 显存 OOM | batch 太大或 fp32 | bf16 + 梯度累积 |
| 推理很慢 | 没用动作分块，每步都前向 | 一次输出整段 chunk |
| 语言指令不跟随 | 只用了机器人数据微调 | 混入少量 VQA 数据共同训练 |

## 我的调试原则

**先闭环，再优化。** 用最笨的方式（最短 chunk、最低频率、最简单的任务）跑通「看到 → 输出 → 执行 → 再看到」，再逐步加大难度。跳过这一步，后面每次失败你都不知道是模型问题还是管道问题。

**每次只改一个变量。** 换主干、换动作头、改数据配比、改 chunk 长度，一次动一项，否则涨点归因不了。

**所有实验都写记录。** 数据条数、微调步数、初始状态采样方式、rollout 次数，缺一项，两周后你就复现不了自己。
