# 本地提交指南（git 命令行）

读完这一篇，你就能在自己的电脑上写笔记、跑一条命令、内容进 GitHub。全程不需要网页操作，也不需要我在场。

## 一、前置检查

```bash
git --version            # 有版本号即可，未安装去 git-scm.com 下载
curl -I https://github.com   # 能返回 200 说明网络通
python3 --version        # 可选，但强烈建议有：md 转 html 靠它
```

Windows 上如果只装了 Git for Windows，命令行的 `python` 常常不存在。这种情况不用装 Python：仓库里带了 GitHub Actions 的构建流程，推上去之后由云端自动把 md 编译成 html（见第六节）。

## 二、一次性配置

### 1. 在 GitHub 建一个空仓库

名字用 `my_vla`（和 `site.json` 里的 `repo` 一致），**不要勾选** Add a README / .gitignore / license，否则首次推送会因为历史不同被拒绝。

### 2. 确认 site.json

```json
{
  "owner": "lijerry630",
  "repo": "my_vla",
  "branch": "main",
  "repo_url": "https://github.com/lijerry630/my_vla"
}
```

`owner` 是用户名，`repo` 是仓库名，脚本靠这两项拼出远程地址。

### 3. 选一种认证方式

**方式 A：Personal Access Token（推荐，脚本里直接可用）**

GitHub → 头像 → Settings → Developer settings：

- Tokens (classic) → Generate new token → 勾选 **repo**
- 或 Fine-grained tokens → 选中该仓库 → Repository permissions → **Contents: Read and write**

生成后只显示一次，先复制。之后每次在终端里临时设置：

```bash
export GITHUB_TOKEN=ghp_xxxxxxxx        # macOS / Linux / Git Bash
```

```powershell
$env:GITHUB_TOKEN = "ghp_xxxxxxxx"      # Windows PowerShell（仅当前窗口有效）
setx GITHUB_TOKEN "ghp_xxxxxxxx"        # 想永久生效（需重开终端）
```

**方式 B：SSH 密钥（不碰 token，长期更省心）**

```bash
ssh-keygen -t ed25519 -C "你的邮箱"      # 一路回车
cat ~/.ssh/id_ed25519.pub               # 把输出贴到 GitHub → Settings → SSH and GPG keys
ssh -T git@github.com                   # 出现 "Hi 用户名!" 即成功
```

用 SSH 时把远程地址改成 `git@github.com:lijerry630/my_vla.git`：

```bash
git remote set-url origin git@github.com:lijerry630/my_vla.git
```

**方式 C：让 git 记住密码（HTTPS）**

```bash
git config --global credential.helper store    # 首次输密码后本地保存
```

### 4. 建仓库时勾了 README 怎么办

如果仓库不是空的（多数人手滑会勾 Add a README），直接 `git init` 再 push 会报 `rejected (fetch first)`，因为两边是两段互不相关的历史。

`tools/setup.sh` / `setup.ps1` 已经处理了这种情况：它会先 `git fetch origin main`，再用 `git reset --soft origin/main` 把本地挂到远程历史后面，于是首次提交是「远程 README 之上再加一个提交」，推送是快进，不会冲突。

手动做的话就是这三条：

```bash
git init -b main
git remote add origin https://github.com/<用户名>/<仓库>.git
git fetch origin main
git reset --soft origin/main   # 关键：HEAD 指向远程提交，文件保留在工作区
git add -A && git commit -m "init: 站点"
git push -u origin main
```

注意 `reset --soft` 不会动你的文件，只移动 HEAD，所以解压出来的内容一个都不会丢。

### 5. 跑一次初始化脚本

**Windows（CMD 里执行，最稳）**

```bat
cd /d "E:\vla\my_vla-站点"
tools\setup.bat
```

**macOS / Linux / Git Bash**

```bash
bash tools/setup.sh
```

**PowerShell 版**：`powershell -ExecutionPolicy Bypass -File tools\setup.ps1`

> 为什么 Windows 优先用 `.bat`：Windows PowerShell 5.1 读取没有 BOM 的 UTF-8 脚本时按本地代码页（中文系统是 GBK）解码，脚本里只要有中文就报「字符串缺少终止符」「缺少右 }」。仓库里的 `.ps1` 已改成纯 ASCII 输出，不再受编码影响；`.bat` 是 CMD 原生，连执行策略都不用动。

它做六件事：初始化仓库 → 设置提交身份和 `core.quotepath` → 把 `origin` 指向目标仓库 → 接上远程已有历史（`git reset --soft origin/main`，避免首次推送被拒）→ 有 Python 就构建一次 → 提交并推送。

看到 `Done: https://github.com/lijerry630/my_vla` 就成了。

### 6. 开启 Pages

仓库 Settings → Pages → Source 选 `Deploy from a branch` → 分支 `main`、目录 `/ (root)` → Save。

一两分钟后访问 `https://lijerry630.github.io/my_vla/`。

## 三、日常提交

### 新增一篇笔记

```bash
python3 tools/build.py new "动作分块与滚动重规划"   # 生成 content/00x-xxx.md 草稿
# 编辑这个 md：title / tags / summary / order / slug 四项按需改
bash tools/push.sh "add: 动作分块笔记"               # 构建 + 提交 + 推送
```

### 导入电脑里已有的 md

```bash
bash tools/push.sh                                   # 先把当前仓库推干净
cp ~/Documents/我的笔记.md content/009-my-note.md     # 复制进来，编号自己起
bash tools/push.sh "add: 导入我的笔记"
```

`publish.py` 的 `up` 子命令做得更省事，会自编号、搬运图片：

```bash
python3 tools/publish.py up ~/Documents/我的笔记.md
```

### 命令对照

| 场景 | bash | PowerShell | Python 版 |
| --- | --- | --- | --- |
| 首次配置 | `bash tools/setup.sh` | `tools\setup.ps1` | `publish.py up` |
| 日常提交 | `bash tools/push.sh "说明"` | `tools\push.ps1 "说明"` | `publish.py up` |
| 只构建不提交 | `python3 tools/build.py` | `python tools/build.py` | `publish.py build` |
| 本地预览 | `bash tools/serve.sh` | `python -m http.server 8000` | `publish.py serve` |

### 手写 git 命令（不想用脚本时）

```bash
python3 tools/build.py      # 改过 md 就必须先构建
git add -A
git commit -m "content: 更新笔记"
git push
```

## 四、为什么必须重新构建

`notes/*.html`、`index.html`、`notes.html` 都是 `content/*.md` 的**生成产物**。GitHub Pages 只认 HTML，所以：

- 只提交 md → 页面不会变，等于白推
- 构建脚本会重算：正文排版、目录、上一篇/下一篇、首页的「最近更新」、标签筛选、阅读时长

`push.sh` 已经内置了这一步，所以平时只要跑脚本就行。

## 五、常见错误

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `remote: Invalid username or token. Password authentication is not supported` | token 没设或失效 | 重新 `export GITHUB_TOKEN`；确认勾了 repo 权限 |
| `! [rejected] main -> main (fetch first)` | 远程已有提交（建仓库时勾了 README） | `git pull --rebase origin main` 后再推 |
| `fatal: 'origin' does not appear to be a git repository` | 没配远程 | `bash tools/setup.sh` 或 `git remote add origin …` |
| `git status` 里中文文件名显示成 `\345\206\231…` | 默认转义 | `git config core.quotepath false` |
| 推送成功但页面 404 | Pages 没开、分支/目录选错，或还在构建 | 查 Settings → Pages，等 1～2 分钟 |
| 页面样式全丢、只有裸文本 | 只上传了 html，没上传 `assets/` | 必须整目录一起提交 |
| `warning: LF will be replaced by CRLF` | Windows 换行符提示 | 可忽略；想消掉跑 `git config core.autocrlf input` |

## 六、本地没有 Python 时的替代方案

仓库自带 `.github/workflows/build.yml`：只要推送到 `main` 且改动落在 `content/`、`theme/`、`tools/build.py`，GitHub 会自己跑一次构建，把 `notes/*.html`、`index.html`、`notes.html` 生成好并提交回来，Pages 随之更新。

所以最省事的组合是：

```bash
git add -A
git commit -m "add: 新笔记"
git push
```

约 1 分钟后刷新 Pages 就能看到新笔记。注意两点：

- 需要仓库的 Actions 处于启用状态（Settings → Actions → General 允许 workflows，默认就是开的）
- 构建结果由机器人提交，提交信息带 `[skip ci]`，不会反复触发

## 七、安全提醒

- token 只放在环境变量或系统凭据里，**不要写进任何被提交的文件**（`site.json`、`.env` 都会被推上去）
- 脚本用 `https://x-access-token:${TOKEN}@…` 的形式临时推送，不会把 token 写进 `.git/config`
- 一旦怀疑泄露：GitHub → Settings → Tokens → Revoke，重新生成一个即可
